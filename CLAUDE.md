# Netdeck

Native macOS app for managing network devices (switches first; routers, firewalls, storage and
server BMCs later). SwiftUI + Swift 6, built as a SwiftPM package. First fully supported platform:
Juniper Junos (EX series, ELS).

## Language rules
- English everywhere in the repository: code, identifiers, comments, docs, commit messages, fixtures.
- The app's development language is English. Every user-facing string goes through `t("English text")`.
- Translations live only in `Sources/NetdeckCore/Resources/<lang>.lproj/Localizable.strings`
  (currently `tr`). When adding a string, add its Turkish translation there too.
- Pass numbers to `t()` as `String` (all placeholders are `%@`).

## Layout
- `Sources/NetdeckCore`: UI-independent core
  - `Transport/`: serial console (termios, IOKit port discovery) and SSH: `NIOSSHTransport` (embedded
    swift-nio-ssh, password auth, host keys pinned in `ssh_known_hosts.json`) by default; `SSHTransport`
    (`/usr/bin/ssh -tt` + one-shot `SSH_ASKPASS`) when `netdeck.useSystemSSH` is on, never in the sandbox.
    Both offer legacy algorithms (DH group 14/1, ssh-rsa, CBC, 3DES) last, for older gear.
  - `Drivers/`: `DeviceDriver` protocol, `DriverFactory`, `ChangeTraits` (how each platform applies changes)
  - `CLI/CLISession`: text CLI session for every platform except Junos; prompts and quirks come from a `CLIDialect`
  - `Cisco/`, `MikroTik/`, `EdgeOS/`, `Aruba/` (AOS-S, AOS-CX), `TPLink/` (Omada / JetStream): dialect, parsers, planner and
    driver per platform; `Fortinet/` (FortiGate): dialect, parsers and a read-only driver
  - `API/`: HTTPS (TOFU certificate pinning in `APIPins`), Redfish (Dell iDRAC; HPE iLO, Supermicro, Lenovo XCC as
    `.redfish`), Synology DSM, TrueNAS; read only apart from Redfish server power actions
  - `Junos/JunosCLI`: text CLI session: login (console/shell/cli), prompt detection, command framing
  - `Junos/OutputParsers`, `JunosConfig`: `show ...` output and `display set` config → models
  - `Junos/ChangePlanner`: staged edits → `set`/`delete` commands (splits interface ranges)
  - `Junos/JunosDriver`: read, preview, `commit confirmed`, confirm, revert, rollback
  - `Model/DeviceCatalog`: device kinds, platforms, `DeviceDetector` (auto-detect from banners/prompts)
  - `Model/FaceplateCatalog`: per-model front panels (`Resources/Faceplates/faceplates.json`, generated by
    `scripts/faceplates-import.py` from `docs/faceplates-research.json`; see `docs/FACEPLATES.md`)
  - `Session/DeviceSession`: `@Observable` per-device state the UI binds to
  - `Support/`: backups, device store, Keychain, localization
- `Sources/Netdeck`: SwiftUI app
- `Vendor/swift-nio-ssh`: SwiftNIO SSH 0.15.1 with legacy key exchange, RSA host keys and CBC/CTR ciphers
  (`Sources/NIOSSH/Legacy/`, every change marked `Netdeck patch`, listed in `PATCHES.md`)
- `Sources/netdeck-probe`: CLI field tool for testing against real hardware (never commits)
- `Tests/NetdeckCoreTests/Fixtures`: real console captures, anonymized (serials, MACs, users, hashes);
  `Fixtures/synthetic/<platform>` holds captures written from vendor docs until real ones replace them

## Commands
- Tests: `swift test` (run alone, not in parallel with other heavy jobs)
- App bundle: `scripts/make-app.sh --open` → `build/Netdeck.app` (`--sandbox`: signed with `Resources/Netdeck.entitlements`;
  `--notarize`: Developer ID + hardened runtime, notarized with the notarytool profile `netdeck`, stapled,
  → `build/Netdeck-<version>-macOS-arm64.zip` for the GitHub release)
- Field test: `NETDECK_PASSWORD=... .build/debug/netdeck-probe --serial /dev/cu.usbserial-XXXX --user root snapshot`
  (`--ssh HOST`, `--api URL`, `--platform junos|cisco|mikrotik|edgeos|aoss|aoscx|tplink|fortigate|idrac|synology|truenas`; `preview "cmd; cmd"`
  shows the device's diff where it has a candidate config and never applies anything)
- Renders for visual checks: `.build/debug/Netdeck --render DIR [--only name,...] [dark] [tr]`
  (`faceplate-models` draws known model panels; `appliance-*` the server/NAS screen)
- Faceplate catalog: `python3 scripts/faceplates-import.py docs/faceplates-research.json`

## Safety rules (hard)
- Never commit anything to a device without the user's explicit approval. Reading and `preview` are fine.
- Every apply arms a device-side timer first (Junos `commit confirmed N`, IOS `revert timer`, EdgeOS
  `commit-confirm`, RouterOS undo script + scheduler, AOS-CX `checkpoint auto N`, AOS-S `cfg-backup` + a one-shot
  `job` running `cfg-restore`, TP-Link `reboot-schedule in N`); it only becomes permanent through a separate
  `confirm()`. AOS-S before 16.05, AOS-CX before 10.06, controller-managed TP-Link switches and FortiGates are read only
  (`ChangeTraits.readOnly`: `DeviceSession.stage` ignores edits and the inspector shows values, not controls).
- TP-Link applies only when running == startup (the restart would drop anyone's unsaved work too); a refused command
  or undo puts the startup settings back with commands and cancels the restart once they match again.
- AOS-S logout asks "save current configuration?": always answer "n" (`AOSSDialect.logout(from:line:)`).
  Never save to the startup/boot config before the user confirms.
- EX4300 rear QSFP+ role changes are operational commands outside the timer: only with the explicit tick.
- HTTPS devices (Redfish BMCs, Synology, TrueNAS) are read only, except server power actions (Redfish
  `ComputerSystem.Reset`), which always need an explicit confirmation in the UI.
- No "Coming soon" in the UI: unsupported options are disabled without a promise.
- Back up the configuration before applying. Stop if the candidate holds someone else's uncommitted changes.
- Log out of serial consoles when done.
- Never put passwords, hashes or real serials/MACs in fixtures or docs.

## Known quirks
- After a root console login, the shell prompt arrives wrapped in `ESC [row;colH ESC H` sequences;
  `JunosCLI.clean` strips them. Cleaning runs on the whole buffer because sequences split across reads.
- csh mangles nested quotes in `cli -c "..."`; the app enters the CLI and sends commands one by one.
- Uplink-module cages appear as `ge-0/2/N` or `xe-0/2/N` depending on the optic. 25G SFP28 DACs show as 1G.
- EX4300 rear QSFP+ ports are Virtual Chassis ports (`show virtual-chassis vc-port`) and absent from `terse`.
- Fixed-width outputs (`show chassis hardware`, `show lldp neighbors`, IOS `show interfaces status`) are parsed
  by header column offsets; keep column alignment when editing fixtures.
- With no known platform, the session logs in as Junos; `JunosCLI` stops at once on another platform's prompt
  and `DeviceSession` hands over to that platform's driver. An IOS-looking prompt (`switch#`) may belong to
  AOS-CX: `CiscoDriver` then hands over again from `show version` (at most two hand-overs per connect).
- AOS-S draws output with VT100 cursor moves; a command without output gets no line break before the prompt,
  only a scroll (`ESC[1M … ESC[1L`), which `CLIDialect.normalize` turns into one. Hostnames may contain spaces.
- TP-Link: no `show version` (CiscoDriver hands over from `show system-info`); the pager erases itself with CR NUL and
  is answered, not turned off (`no clipaging` is a config line); `exit` from `#` keeps the session, only `logout` ends
  it, and abandoned sessions fill the switch's small session table. Commands go out with CR LF.
- FortiOS: the prompt has a blank before `#` (`FGT60F # `, `FGT60F (global) # `); the `--More--` pager is answered, never
  turned off (`config system console` is a configuration change). Netdeck only sends `get`/`show`/`diagnose ... list`; with
  VDOMs it reads inside `config global` and leaves with `end`; it never `edit`s (that creates missing objects). A context
  left on a console is left with `abort` (`end` would save someone's edits).
- IOS console log lines (`%LINK-3-UPDOWN`) may follow the prompt; `CLIDialect.isAsyncMessage` keeps them from
  hiding it. RouterOS logins use `user+ct511w4098h` (no colors, wide terminal).

# TP-Link Omada / JetStream fixtures (synthetic)

These captures are **synthetic**. No TP-Link switch was available when the module was written. They follow the
TP-Link "Managed Switches CLI Reference Guide" (1900000380, 2025), the T1600G series CLI guide, TP-Link's
configuration guides (802.1Q VLAN, LLDP, LAG, MAC address table), and public raw captures of real switches:
an SX3832 / SG3452 automation repository (running configuration with the pager, `reboot-schedule` behaviour),
TL-SG2424 telnet captures (`show interface status`, `show mac address-table`), an Oxidized issue with a
TL-SG3452X `show system-info`, and the Netmiko `tplink_jetstream` driver. Replace them with real, anonymized
captures once a switch is available.

Each file is what `CLISession` sees for one command after escape sequences are removed: the echoed command, the
output and the prompt (`SW-EDGE-02#`).

| File | Command | Notes |
| --- | --- | --- |
| `sg3428-show-system-info.txt` | `show system-info` | "Label - value" lines; the model is the first word of "Hardware Version" |
| `sg3428-running-config.txt` | `show running-config` | `!SG3428` first line, `#` padding, VLAN names quoted, general-port membership (`switchport general allowed vlan … untagged/tagged`, `switchport pvid`, `no switchport general allowed vlan 1`), a LAG (`channel-group 1 mode active` on Gi1/0/23-24, VLANs on `port-channel 1`), a port untagged in two VLANs (Gi1/0/4) |
| `sg3428-show-vlan-brief.txt` | `show vlan brief` | VLAN, name, status and a port list |
| `sg3428-interface-status.txt` | `show interface status` | the older column layout (Port, Status, Speed, Duplex, FlowCtrl, Active-Medium); newer firmware may add columns, which are found by header name |
| `sg3428-mac-address-table.txt` | `show mac address-table` | T-series layout, an entry on `Po1`, the switch's own `CPU` entry |
| `sg3428-lldp-neighbor-information.txt` | `show lldp neighbor-information` | detail blocks per local port ("gigabitEthernet 1/0/1:"), a wrapped system description |

The raw pager (`Press any key to continue (Q to quit)`, erased with CR NUL and spaces once answered) is built in
`TPLinkTests` from the bytes seen in the public captures.

Assumptions from the documentation that a real switch should confirm: `switchport general allowed vlan X tagged`
on a port that is untagged in X changes it to tagged; `show startup-config` prints the same lines as
`show running-config` when nothing is unsaved; `reboot-schedule in N` asks "Continue? (Y/N)" and
`reboot-schedule cancel` asks nothing (seen on an SX3832); `show interface status` on current firmware keeps the
Port and Status columns; adopted switches carry `sdm prefer omada` or `profile network id` lines.

Only documentation values are used: addresses from 192.0.2.0/24, MAC addresses from 00-00-5E-00-53-xx
(RFC 7042), serial numbers `TEST…`, no passwords or hashes. The files were generated by a small script so the
columns line up.

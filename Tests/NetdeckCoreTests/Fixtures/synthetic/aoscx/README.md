# HPE Aruba AOS-CX fixtures (synthetic)

These captures are **synthetic**. No AOS-CX switch was available when the AOS-CX module was written. They
follow HPE's AOS-CX 10.10 Command-Line Interface Guide (6000/6100), the HPE "CLI Reference Guide for
ArubaOS-CX, ArubaOS-Switch, Comware and Cisco IOS", and public raw captures of real switches (Oxidized test
data for 6000, 6100, 6300M, 6410 and 8325: `show version`, `show system`, `show running-config`). Replace them
with real, anonymized captures once a switch is available.

Each file is what `CLISession` receives for one command: the echoed command on the first line, the output,
and the prompt (`sw-cx-01# `, with the trailing space AOS-CX prints) on the last line.

| File | Command | Notes |
| --- | --- | --- |
| `6300m-show-version.txt` | `show version` | verbatim layout of a 6300M on FL.10.13.1101 |
| `6300m-show-system.txt` | `show system` | Product Name, Chassis Serial Nbr, ArubaOS-CX Version |
| `6300m-running-config.txt` | `show running-config` | `vlan 1,99` (VLANs without settings on one line), named VLANs, a VLAN description, `interface lag 1` trunk, LAG members (`lag 1`), access and trunk ports with `no routing`, `vlan trunk allowed all`, a routed port with an address, shut ports |
| `6300m-interface-brief.txt` | `show interface brief` | two header lines, empty Reason on up ports, "No XCVR installed" on an empty cage, the Description column of 10.05 and later |
| `6300m-show-vlan.txt` | `show vlan` | default names `DEFAULT_VLAN_1` and `VLAN99` |
| `6300m-mac-address-table.txt` | `show mac-address-table` | `xx:xx:xx:xx:xx:xx` addresses, a LAG port |
| `6300m-lldp-neighbor-info.txt` | `show lldp neighbor-info` | a phone that sends its MAC as port ID, port descriptions and system names with spaces |

The table layouts of `show interface brief`, `show vlan`, `show mac-address-table` and `show lldp neighbor-info`
come from the documentation, whose PDF text loses exact spacing; the parsers locate columns from the header
and treat the first columns as single words, so they don't depend on exact widths.

Assumptions from the documentation that a real switch should confirm:

- `vlan trunk native N` also sets `vlan trunk allowed all`, and `vlan trunk allowed <list>` given right after it
  leaves only that list (the guide's own example). Removing a trunk's last allowed VLAN makes it carry all VLANs.
- `checkpoint auto N` prints "Auto checkpoint mode expires in N minute(s)"; a second one fails with
  "Checkpoint auto timer is already ON". The reminder "WARNING" may appear right after the prompt.

Only documentation values are used: addresses from 192.0.2.0/24, MAC addresses `48:a9:8a:00:…`, serial numbers
`TEST…`, no passwords or hashes (the `user` line keeps `********` as Oxidized does).

The files were generated by a small script so the columns line up; keep the alignment when editing them.

# HPE Aruba AOS-S (ProCurve) fixtures (synthetic)

These captures are **synthetic**. No AOS-S switch was available when the AOS-S module was written. They follow
the HP Switch Software Management and Configuration Guide (K/KA.15.14), the HPE "ArubaOS-Switch and Cisco IOS
CLI Reference Guide" (K.16.03), the white paper "Configuration Restore Without Reboot, ArubaOS-Switch 16.05", and
public raw captures of real switches (ntc-templates `hp_procurve` test data; an Oxidized SSH capture of a 2930M
on WC.16.11.0028 for `show version`, `show modules`, the running configuration and the VT100 output).
Replace them with real, anonymized captures once a switch is available.

Each `.txt` file except the `raw-*` ones is what `CLISession` sees for one command after escape sequences are
removed: the echoed command, the output and the prompt (`SW-ACCESS-01# `).

| File | Command | Notes |
| --- | --- | --- |
| `2930m-show-version.txt` | `show version` | verbatim layout ("Image stamp:", the revision on its own line) |
| `2930m-show-system.txt` | `show system` | two "key : value" columns per line |
| `2930m-show-modules.txt` | `show modules` | "Chassis: 2930M-48G-PoE+  JL322A  Serial Number:" |
| `2930m-running-config.txt` | `show running-config` | membership on the VLAN side (`untagged`, `tagged`, `no untagged`), a trunk group (`trunk A3-A4 trk1 lacp`), quoted names with spaces, `disable` |
| `2930m-interfaces-brief.txt` | `show interfaces brief` | the wide Port column, trunk members as `A3-Trk1`, an empty cage with no type |
| `2930m-show-vlans.txt` | `show vlans` | a VLAN name with a space |
| `2930m-mac-address.txt` | `show mac-address` | `xxxxxx-xxxxxx` addresses with the VLAN column of 16.x |
| `2930m-lldp-remote-device.txt` | `show lldp info remote-device` | chassis and port IDs as hex bytes with spaces |
| `raw-no-output-command.txt` | `no page` | raw bytes as the switch sends them (from the Oxidized capture): no line break between the echo and the prompt, only a terminal scroll (`ESC[1M … ESC[1L`) |
| `raw-config-command.txt` | `name "uplink 1"` | the same in an interface context |

Assumptions from the documentation that a real switch should confirm: `vlan N untagged P` moves the port from
its previous untagged VLAN; `job NAME delay DD:HH:MM "ALIAS" count 1` runs the alias once without asking
`cfg-restore`'s "Continue (y/n)?" (HPE's own automatic-rollback recipe); `show job NAME` prints
"Job Status" and "Run Count".

Only documentation values are used: addresses from 192.0.2.0/24, MAC addresses `48a98a-…`, serial numbers
`TEST…`, no passwords or hashes. The files were generated by a small script so the columns line up.
